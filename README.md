# ClickHouse Schema Graph

Интерактивное приложение на Python: подключается к ClickHouse и показывает все
сущности базы данных (таблицы, представления, материализованные представления,
словари) в виде **кликабельного графа связей** — например, для представления
отображаются таблицы, которые оно использует.

Стек: Streamlit + streamlit-agraph (интерактивный граф) + clickhouse-connect.

## Быстрый старт

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/streamlit run app.py   # http://localhost:8501
```

Подключение настраивается **прямо в интерфейсе**:
- при запуске — форма на стартовом экране (хост, порт, пользователь, пароль,
  HTTPS/TLS) с кнопкой «🔌 Подключиться»; подключение валидируется только по
  кнопке, а не на каждый ввод символа;
- после подключения — статус («🟢 Подключено: host:port · user») и список баз
  в боковой панели; там же экспандер «⚙️ Параметры подключения» с кнопкой
  «Переподключиться»;
- ошибка подключения показывается в интерфейсе, приложение возвращает к форме.

Переменные окружения `CLICKHOUSE_HOST`, `CLICKHOUSE_PORT` (по умолчанию 8123,
HTTP), `CLICKHOUSE_USER`, `CLICKHOUSE_PASSWORD`, `CLICKHOUSE_DATABASE`,
`CLICKHOUSE_SECURE=1` и сам список баз предоставляют дефолты формы.

Демо-данные для проверки без своей схемы:

```bash
clickhouse-client --multiquery < demo/demo_schema.sql   # создаёт базу `shop`
```

## Возможности

- Узлы графа окрашены по типу объекта (таблица / представление / мат-view /
  словарь / объект из другой базы), размер узла зависит от числа связей.
- Клик по узлу — панель с колонками, CREATE-запросом, списками
  «использует» / «используется в».
- Фильтры: типы объектов, показ `system`-объектов, объекты из других баз,
  кнопка «🔄 Обновить схему» (пере-читать метаданные).
- Технические (шард-локальные) таблицы `x_*`, по которым собираются
  `Distributed`-таблицы, на графе скрыты — они не показываются ни как узлы,
  ни как концы связей. Список префиксов — константа `HIDDEN_PREFIXES` в `app.py`.
- Типы связей: «использует» (FROM/JOIN в представлении или мат-view),
  «TO-цель» (мат-view → целевая таблица), «источник» (словарь → исходная таблица).

## Как определяются зависимости

В ClickHouse нет первоклассной мапы «представление → таблицы». Приложение
регулярными выражениями разбирает `create_table_query` каждого объекта из
`system.tables`: пропускает комментарии, подзапросы `FROM (SELECT ...`,
функции-генераторы (`FROM numbers(10)`), SQL-ключевые слова (`TO DISK` в TTL),
псевдонимы CTE (`WITH t AS (...)`) и само-ссылки. Разбор словаря опирается на
именованные параметры `SOURCE(CLICKHOUSE(... db 'x' table 'y' ...))`.

Ограничения: словари с позиционными аргументами `SOURCE`, `remote`/`cluster`
и DDL с цитатами и переносами строк вне обычных форм могут не распознаться;
ложные срабатывания из-за строковых литералов, содержащих `FROM`/`JOIN`.
